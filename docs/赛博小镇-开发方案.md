## 1. 概述与定位

赛博小镇是一个《星露谷物语》式农场乡村小镇的「活体世界仿真」demo，**运行在 PC 端（无手机客户端）**。玩家是新搬来接手农场的农夫，用**键盘走动**在三个地点之间穿行；交流走游戏内的**「类手机菜单」**（拟物 UI）：当面说（F2F 广播）/ 私聊（RDC，走近 NPC 按 E 直达）/ 群聊（GRP）。NPC 由 LLM 驱动、自主生活与移动，**允许沉默发呆——生活感优先**；玩家不调 LLM，其操作被翻译成世界动作经总线注入，与 NPC 动作等权。

- **题材**：星露谷风格农场小镇。**暂无剧情**，只需基础人设 + 大致背景。`docs/《Dropout in Silicon Valley》.md` 蓝本已作废，不参考。
- **目标**：跑通「后端持续驱动 agent_world tick → 每拍快照经 WebSocket 推 Godot → 玩家键盘+菜单操作注入世界」这条活体闭环。
- **本期 = 垂直切片范围**：3 地点（`farm` / `square` / `saloon`）+ 3 NPC（杂货铺老板 / 酒馆老板娘 / 邻居农夫）+ 1 玩家农夫；F2F/RDC/GRP 三渠道 + 键盘地点间移动；薄层好感度注入 NPC 提示词；记忆只用引擎自带 SegmentStore，长期向量记忆延后。**多人进入互动列入后续扩展（§14），本期单人本地。**

标准姿势模板：`agent_world/demo/`（`scenario.yaml` + `demo_agent.py` + `run_demo.py`）是引擎自带可跑范例，本方案的世界装配 1:1 照搬其 `_build_kernel` / `_seed_world`。

### 三条数据流

**① tick 主循环（世界心跳）**
`tick_loop` while-true → `await world_step.run_one_tick()`（`world/step.py:80-200`，11 步管道）→ 拍末 `build_snapshot()` 只读 world → `ws_hub.broadcast(snapshot)` → `await asyncio.sleep(...)`（固定墙钟补齐）。`world.t` 必进 1：step 11 在 `step.py:195` 调用 `_advance_clock`（定义于 `step.py:341`），即使上游全失败。

**② 玩家命令注入**
前端（键盘走进 zone 自动发 `request_move`；菜单发言）→ `/ws/world` 上行 `{action, kwargs}` → `ws_hub` `player_queue.put_nowait` → 下一拍 step 7（`_run_place`，`step.py:253-290`）中 `PlayerAgent.perform_action_by_llm` 非阻塞出队一条 → 包成 `_Response(info={"tool_calls":[_ToolCall(...)]})` → `_extract_actions`（`step.py:433-483`）解析 → `dispatcher.dispatch`（`dispatcher.py:163-213`）落世界。**前提**：玩家 id 必须在该拍 `pick_active` 返回列表里（本方案 scheduler 恒含玩家），玩家不调 LLM 故不烧 token。

**③ 每拍快照推送**
`build_snapshot` 只读 `world_state` + `world_db._conn`（与 `run_demo._print_tick_report` 同款 SELECT）拼 JSON → `ws_hub.broadcast`。读时机严格在 `run_one_tick()` 返回之后（t 已进）；快照写入 post-advance 的 `world.clock.t`，前端据此对齐。

## 4. agent_world 集成点（核心章节）

### 4.1 WorldStep 驱动

- 构造：`WorldStep.__init__(world_state, perception_builder, dispatcher, script_engine=None, pool_manager=None, f2f_bus, rdc_bus, grp_bus, segment_store, compressor=None, scheduler, sim_id="cyber_town")`，`world/step.py:46-74`。所有可选依赖 duck-typed + None 容错。本切片：`script_engine / compressor / retriever = None`，`pool_manager = _NullPoolManager()` 实例（**不传 None**——dispatcher 的 pools 路径无 None-check），`scheduler = ActivationScheduler`。
- ⚠️ **dispatcher / perception_builder 必须非 None**：step 7.b 的 `dispatcher.dispatch`（`step.py:283`）**无 None-check**（仅 step 9 在 `step.py:168` 有保护）。`world_factory.build_world()` 构造 WorldStep 时显式断言二者非 None，并写测试守住；红线下不改 `step.py`。
- 心跳：`report = await world_step.run_one_tick()`，`step.py:80-200`。返回 `{'t','next_t','active','places','failures'}`——**只有这 5 个键，没有 obs/消息内容**（好感度规则法不能依赖它拿消息，见 §9）。
- 连续服务用显式循环 + `asyncio.sleep`，**不要** `run_loop(N)`（`step.py:204` 起的 `run_loop` 是同步 N 次、不带延迟）。

> ⚠️ **不变量**：F2F 同拍同地点可见；RDC/GRP/MOVE 锁步下拍生效；玩家 `request_move` 当拍仍在旧地点（step 9 才 commit）；`UPDATE_STATE` 当拍写入但下一拍 perception 才读到。

### 4.2 PlayerAgent 虚拟 agent 适配

实现 `cyber_town/backend/player_agent.py`，满足 agent duck-type 契约（`step.py:264-307` + `demo_agent.py` 参考）。`_decide`（`step.py:292-307`）先试 `perform_action_by_llm(world, t)`，`TypeError` 再试无参版。

```python
async def perform_action_by_llm(self, world, t) -> _Response:
    try:
        cmd = self.command_queue.get_nowait()          # 非阻塞，不卡 tick
    except asyncio.QueueEmpty:
        return _Response(info={"tool_calls": [_ToolCall("do_nothing", {})]})
    atype, kwargs = self._translate(cmd)               # 见 §6 上行映射
    return _Response(info={"tool_calls": [_ToolCall(atype, kwargs)]})
```

`_extract_actions`（`step.py:433-483`）识别 `.info["tool_calls"]`，读每项 `tool_name`/`name` + `args`/`arguments`。`_Response`/`_ToolCall` 是 `demo_agent.py` 的私有下划线符号——**在 `player_agent.py` 本地复刻同形 dataclass**，不直接 import demo 内部实现。

PlayerAgent 须提供 duck-type 字段（哪怕空串）：`agent_id, name, last_message_seen_at, soul, long_term_goal, current_state, current_state_set_at, short_term_goal, groups`。两个易踩的坑：
- **`groups` 必须初始化为 `[{"group_id":100,...}]`**（或启动时从 `world_db` 同步）：`_seed_world` 只写 DB 层 group_member，agent 对象字段不会自动填；空列表会让前端群聊页拿不到群元信息。
- **`last_message_seen_at` 会被引擎每拍覆写**：step 7 在每个 active agent 决策后无条件推进它到 t（`step.py:271-277`，与是否调 LLM 无关）——所以快照层**不能**复用该字段做消息去重游标（见 §6.1）。

`name_directory` 必须含玩家名，避免 NPC prompt 显示裸 id。

### 4.3 激活调度（同场每拍 + 异地低频心跳）

step 4 `_pick_active`（`step.py:212-236`）：若 `scheduler` 非 None 且 `pick_active` 返回非 None，则用之覆盖默认全激活（`step.py:223-227` 提前 return）；返回 `[]` 合法。

```python
class ActivationScheduler:
    """同地点 NPC 每拍激活；异地 NPC 每 HEARTBEAT_EVERY 拍激活一次（按 id 错峰）。

    世界不冻结：玩家不在场的地点，NPC 仍会低频地干活/串门/群里冒泡。
    """
    HEARTBEAT_EVERY = 10          # ≈ 25s 一次，M0 压测后可调

    def __init__(self, player_id: int): self.player_id = player_id

    def pick_active(self, world, t):
        active = [self.player_id]                       # 玩家必入列（注入命令用，零 token）
        ppl = world.location_of(self.player_id)
        for aid in world.agents:
            if aid == self.player_id:
                continue
            if world.location_of(aid) == ppl:
                active.append(aid)                      # 同场：每拍激活
            elif (t + aid) % self.HEARTBEAT_EVERY == 0:
                active.append(aid)                      # 异地：低频心跳，错峰唤醒
        return active
```

> ⚠️ **互斥规则**：一旦提供 scheduler 且返回非 None，per-agent `activity_level` 门控被完全跳过（`step.py:223-236`），二者不可叠加——本切片**只用 scheduler**。
> ⚠️ **agent_id=0 陷阱**：`step.py:233` 的 `aid = _coerce_agent_id(key) or _coerce_agent_id(agent)` 对 id=0 是真值陷阱；本方案安全的前提是 scheduler **永远返回非 None 列表**（走 223-227 提前 return，绕开 233 行）。**绝不以 scheduler=None 模式跑 cyber_town**；写测试断言「玩家 id=0 每拍在 active 列表」。

### 4.4 dispatcher 动作注入与拍末移动结算

`dispatcher = ActionDispatcher(world_state, f2f_bus, rdc_bus, grp_bus, pool_manager=_NullPoolManager(), script_engine=None, compressor=None, segment_store=segment_store)`，`world/dispatcher.py:134-152`。

- 入口 `dispatch(agent_id, action_type, t, **kwargs)`，`dispatcher.py:163-213`。`action_type` 接受 str（自动 coerce 为 `ActionType`，`dispatcher.py:180-185`）；未知类型 → `{'success':False,'reason':'unknown_action'}`，**不抛异常、静默丢弃**（`dispatcher.py:188-194`）——这正是 `adjust_affinity` 必须在进 dispatcher 前被抽走的原因（§9）。
- 路由表 `_route`（`dispatcher.py:219-303`）：`speak_to_local`→`f2f.send`（227-229）；`send_message`→`rdc.send`（231-240）；`send_to_group`/`create_group`/`join_group`/`leave_group`→`grp.*`；`request_move`→`enqueue_move`（262-265）；`update_state`/`update_short_term_goal`→世界写（274-277 路由；`_set_current_state` 完整实现含 fallback 在 417-448）。
- 移动两段式：step 7 `enqueue_move`（`dispatcher.py:309-313`）入 `pending_moves`，**立即返回不移动**；step 9 `commit_pending_moves(t)`（`dispatcher.py:315-357`）逐个 `places.move`，未知地点 silent fail。注意：**`place_store.move()` 实际没有 capacity 检查**（dispatcher 注释里的 capacity-conflict 是规划文案）——超员监控需后端自算自记日志。
- 成功动作自动 `segment_store.append(agent_id, t, action_type.value, dict(kwargs))`（`dispatcher.py:203-211`），供防 loop。

### 4.5 三总线

| 渠道 | 触发 | 门控 | 时序 | 引擎 API |
|---|---|---|---|---|
| F2F | `speak_to_local` | `phi_f2f`=同地点（`connectivity.py:61-66`） | `arrive_at=t`，**同拍**同地点后续决策者可见 | `FaceToFaceBus.send`（`buses/face_to_face.py:46-90`，insert 在 L72/L85）；写 `direct_message`(F2F)+`overhear` |
| RDC | `send_message` | `phi_rdc`=contact ∧ 双方 `signal_uplink` ∧ coverage 可达（`connectivity.py:68-79`） | 成功 `arrive_at=t+latency`（三级：coverage>channel_config>1）；同地点走 self-edge latency=0；失败 `delivered=0` 下拍透传 `recent_failed_attempts` | `RemoteMessageBus.send`（`buses/remote_message.py:74-124`）→ `SendResult{success,arrive_at,message_id}` |
| GRP | `send_to_group`（需先入群） | `phi_grp`=成员 ∧ `signal_uplink` ∧ self-coverage（`connectivity.py:81-91`） | `arrive_at=t+grp_delay`；不可达成员 `delivered=0` 由 step 5 `sweep_undelivered` 重投 | `GroupMessageBus.send_to_group`（`buses/group_message.py:141-177`） |

`RDC_CAPABILITY == GRP_CAPABILITY == "signal_uplink"`（`connectivity.py:28-29`）——收发双方都需有。全部消息统一落 `direct_message` 表，`channel_type ∈ {F2F,RDC,GRP}`。
**按 E 私聊的通道语义**：私聊一律走 RDC `send_message`（悄悄话，旁人收不到）；同地点时经 self-edge（latency 0）几乎即达。「当面说」页才走 F2F（出声，全场都听见、NPC 能互相接话）。

### 4.6 perception 拼快照（NPC 视角）

热查询：`fetch_arrived_for(recipient,t,last_seen)`（`world_db.py:377-389`，`delivered=1 ∧ arrive_at<=t ∧ arrive_at>last_seen`）、`fetch_overhear_for`、`fetch_failed_attempts_for(sender,t-1)`、`fetch_for_agent(agent,t-1)`（群事件 TTL=1 拍）、`fetch_f2f_history_at`。

### 4.7 好感度注入（不改引擎）

注入点不碰引擎：`CyberTownNPC`（DemoAgent 形状，自有）在 `perform_action_by_llm` 内 `await perception.build()` 拿到 `(sys_prompt, obs)` **之后、调 LLM 之前**，把「# 我对在场各人的态度」段 append 到 `sys_prompt` 末尾（第 6 段，不动引擎硬编码的前 5 段，不污染 `current_state`）。审计已确认此路线可行（build 返回纯 str；引擎对一拍多 tool_calls **全量 dispatch**，`adjust_affinity` 与 `speak_to_local` 同拍并发产出可行）。详见第 9 节。

### 4.8 行为自主性原则（W3 确立，W4 补充「响应性纪律」）

> **W4 私信修复（三层根因，2026-06-10）**：①self-edge latency=0 使同场私信
> arrive_at=t，与引擎感知游标每拍推进+地点内随机决策序竞态，约半数私信永久
> 掉出 (last_seen,t] 窗口——loader 已改 latency=1（F2F 不受影响：其 arrive_at
> 写死=t 且 phi_f2f 不依赖 coverage）；②私信混排消息堆被小模型忽略——感知层
> 提级单列渲染+「在等回音/对方在场可当面答」事实标注；③W3 瘦身误删响应纪律——
> 「别人特意发你的私信别已读不回（怎么答、答什么由你）」作为第三条纪律回归：
> **响应性是社交纪律，不是行为脚本**。

经 21-agent 自主性审计 + 用户拍板，本项目对「agent 行为」的铁律：

1. **行为内容零代理**：说什么/对谁/去哪/改什么状态/观感怎么变，只能出自
   LLM tool_calls；后端不得按规则替 NPC 产生或修改这些（好感度规则法已因此移除）。
2. **行动时机零代理**：全员每拍激活，无心跳门控。
3. **提示词只描述不指令**：环境/事实/机制说明 + 中性总括；行为模板列表已瘦身，
   自省提醒条件化（仅事件触发），避免高频重复的概率诱导。
4. **前端只渲染有背书的事实**：气泡=真实消息、状态条=current_state、位置=引擎
   结算、爱心=affinity 数据；地点内游走由 NPC 自写的 current_state 动态语义驱动
   （静态语义/无线索则站定），不再无条件随机散步。
5. **允许的非自主层**（声明在案）：fail-soft 降级（超时 do_nothing）、世界物理
   规则（F2F 同地点/RDC 关系门控）、表现层插值（站位锚点/步行路径/朝向）、
   Mock 测试剧本（生产不生效）。

### 5.2 tick 循环任务（`tick_loop.py`）

```python
async def tick_loop(asm, hub, affinity_mgr):
    while True:
        t0 = time.monotonic()
        try:
            report = await asm.world_step.run_one_tick()        # 心跳
            affinity_mgr.apply_rule_based(asm, report)          # 规则法底噪：直接查 world_db（§9）
            snap = build_snapshot(asm, report, affinity_mgr)
            await hub.broadcast(snap)
        except asyncio.CancelledError:
            break                                               # lifespan shutdown 优雅退出
        except Exception as e:
            log.error("tick failed: %s", e)
        finally:
            elapsed = time.monotonic() - t0
        await asyncio.sleep(max(0.0, TICK_SECONDS - elapsed))   # 固定墙钟补齐
```

`run_one_tick` 受 DMXAPI flash 延迟（1–3s）主导，同地点多 NPC **串行**决策（`_run_place` 地点内串行）最坏 3 NPC ≈ 9s，可能远超 TICK_SECONDS——届时本拍结束立即进下拍（**变速拍**），前端必须按快照携带的 `t` 渲染而非假设固定节拍。降级策略：给单次 LLM 调用加 per-call 超时（超时该 NPC 本拍 `do_nothing`）；M0 真实压测后锁定 TICK_SECONDS 与超时值。

### 5.3 LLM 接入（`llm_client.py`）

`AsyncOpenAI(base_url="https://api.deepseek.com", api_key=os.environ["LLM_API_KEY"], timeout=...)`（DeepSeek 官方 API），model `deepseek-v4-flash`——**已实测**：/models 列表确认、tool_calls 3/3 稳定产出、单次延迟 avg 2.7s / max 3.5s（注意 `deepseek-chat`/`deepseek-reasoner` 将于 2026/07 弃用，勿用）。读 `.env` 复用 `run_demo._load_dotenv_into_environ` 思路。单例供所有 NPC 共享；另提供 `MockLLMClient`（同调用面、离线剧本）供无网冒烟与 CI。`max_tokens=400` 仅限输出，多 tool_calls 场景若频繁截断（日志观察）则调大。

### 5.4 启动流程（`main.py`，用 lifespan 而非 on_event）

1. load `scenario.yaml` + `.env`（`DMXAPI_KEY`）。
2. `asm = await build_world(scenario)`：`WorldDB+init_schema`（**必须在 create_task(tick_loop) 之前同步完成**，加断言防重构破坏）→ `loader.seed_into_db`（places→coverage→**self-edge 补全（照搬 run_demo.py:156-160）**→agent_location→capabilities→groups→relations + `connectivity.set_group_members`）→ 各 store `load_from_db` → 三总线 → `SegmentStore()` → `PerceptionBuilder(中文 headers)` → `WorldState` → `ActionDispatcher(pool=_NullPoolManager())` → **构建 `name_directory`(id→name)** → 建 `CyberTownNPC×3`+`PlayerAgent×1`（`register_agent`；玩家 `groups` 预填）→ `WorldStep(scheduler=ActivationScheduler(PLAYER_ID))`（断言 dispatcher/perception 非 None）。
3. `affinity_store.seed()`（幂等）。
4. `tick_task = asyncio.create_task(tick_loop(asm, ws_hub, affinity_mgr))`。
5. **shutdown**（lifespan 退出段）：`tick_task.cancel()` → `await tick_task`（吞 CancelledError）→ `world_db.close()`——防 SIGTERM 时后台残写 world.db（参照引擎 runner 的清理姿势 `runner/run_agent_world_simulation.py:585-591`）。

WS 端点：`@app.websocket("/ws/world")` → `ws_hub.register(ws)`；循环 `recv` 玩家命令 → `player_queue.put_nowait`（队列无界不会 QueueFull；前端做发送节流）。广播由 `tick_loop` 每拍统一推。

### 5.5 架构决策：为何不复用引擎 runner/Flask

引擎自带 runner 走子进程 + 文件 IPC（`ipc/`），Flask（`app/`）多为桩（`app/api/simulation.py` 的 world_state 端点仍是 "TODO L3"）。文件 IPC 轮询对 2.5s 高频 WS 推送不友好，子进程隔离 world.db 引入跨进程单写者争用。本方案照搬 `run_demo.py` 的**单进程内联装配**，FastAPI 在自己 asyncio loop 跑 `tick_loop` + WS，零 IPC。

### 6.2 上行：玩家命令（进 `PlayerAgent.command_queue`）

```json
{"action":"request_move",  "client_seq":7,  "kwargs":{"place_id":"saloon"}}
{"action":"speak_to_local","client_seq":8,  "kwargs":{"content":"大家早上好！"}}
{"action":"send_message",  "client_seq":9,  "kwargs":{"target":1,"content":"晚点来农场吗？"}}
{"action":"send_to_group", "client_seq":10, "kwargs":{"group_id":100,"content":"谁要换鸡蛋？"}}
```

- `request_move` 由**键盘走进 zone 自动触发**（前端发出，玩家无感）；其余三条来自类手机菜单。
- `action` 值**严格等于** `ActionType.value`；`kwargs` key 对齐 `dispatcher._route`：`send_message` 用 `target+content`，`request_move` 用 `place_id`。后端：`dispatcher.dispatch(PLAYER_ID, action, world.clock.t, **kwargs)`。
- 玩家自己发的消息由**前端本地即时回显**（聊天面板左右分栏 + F2F 同时出自己头顶气泡），不等快照、不改协议。

错误码（error 信封）：`UNAUTHENTICATED / BAD_REQUEST / UNKNOWN_COMMAND / INVALID_TARGET / NOT_CO_LOCATED / NO_COVERAGE / NOT_GROUP_MEMBER / RATE_LIMITED / INTERNAL`。RDC/GRP 门控失败是 `delivered=0` 静默，必须经 `player_view.failed` 回前端做明确反馈。

> ⚠️ **协议语义提醒**：(1) `ack` 只确认「已入世界」，NPC 回复要到 t+1 或更晚 snapshot 才出现；(2) `request_move` 当拍仍在旧地点，前端 pending 期以快照 `location` 为准（期间灰化「当面说」输入，防止说给旧地点的人）；(3) `bubble` 与 `player_view.f2f` 同源同句——前端约定：气泡=实时主显，聊天记录=留档（D18）；(4) `player_view` 各列按 `message_id` 去重增量渲染。

### 7.2 移动：键盘走动（唯一移动方式）

WASD/方向键移动 + 4 向动画 + 脚步声（借鉴参考章节 `player.gd` 的输入与音效模式）。每 place 一个 `Area2D` zone + 若干 `Marker2D` 锚点。玩家 body 进入某 zone 且 ≠ 当前已确认 place → `WorldNet.send_request_move(place_id)` 并进 `pending` 态；待快照 `self.location==目标` 才清 pending。pending 期：**不回弹精灵、不乐观瞬移**，仅灰化「当面说」输入（F2F 可达性以引擎 location 为准）。zone 的 Area2D 与 NPC 碰撞体分图层，避免误触发。地点内自由走纯前端表现、不上行。

### 7.3 NPC 平滑移动

NPC 状态机 `{IDLE, WANDER, WALKING}`：快照里 `location` 变了 → `WALKING`，每帧 `global_position.move_toward(walk_target, speed*delta)`（持续逼近、到位即停——**不写死定长 Tween**，适配变速拍），到达转 `WANDER`（锚点 `wander_range` 内随机游走，借鉴参考章节 `npc.gd`）。用 position 插值，不调 `move_and_slide` 物理（避免与玩家推挤）。视觉不连通区走预设航点。同拍多 NPC 动作引擎内随机串行、无顺序约定——前端按快照一次性渲染即可。

### 7.4 WS 客户端（`WorldNet` autoload）

`WebSocketPeer` 连 `ws://localhost:8000/ws/world`。`_process` 中**先 `poll()`（只推进连接状态机，不返回数据），再按 `get_available_packet_count()` 循环 `get_packet()`** 取包、解析 JSON 后按 `type` 分发信号：`snapshot_received` / `hello_received` / `connection_changed`。上行封装 `send_request_move / send_speak_to_local / send_send_message / send_to_group`，带本地节流（同命令 ≥0.3s 间隔）。断线指数退避重连，重连后用快照全量重建（无本地权威状态）。`SnapshotDecoder` 集中归一 JSON、防御缺字段、容忍 `null`。

### 7.5 类手机菜单（PhoneMenu）+ 按 E 直达

- **呼出**：Tab/Esc 开关菜单；菜单开启时玩家停止移动（`set_interacting` 模式，借鉴参考章节）。
- **当面说页**：输入→`speak_to_local`，对当前地点所有人出声（在场 NPC 都听见、能互相接话）；列出在场者；玩家 pending 移动期间置灰。
- **私聊页**：联系人列表来自快照 `contacts`（`can_reach_now=false` 置灰+显示 reason；`relation_types` 由前端映射显示名，如 neighbor→邻居）；每人一个会话页，输入→`send_message`。**走近 NPC 按 E = 自动打开菜单并直达该 NPC 的私聊会话页**（NPCSensor 检测最近 NPC，HintLabel 提示），无需点击。
- **群聊页**：「镇民群」会话，输入→`send_to_group`；M1→M2 期间置灰。
- **聊天记录页**：全渠道消息留档（含 overheard 旁听），按 `message_id` 去重、本地归档。
- **呈现分工（D18）**：F2F 类消息（自己说的+别人说的+旁听）实时出头顶气泡（数秒后淡出）+ 进聊天记录；RDC/GRP 只进面板，菜单图标出**角标提醒**+提示音。
- 每次发送本地回显并禁用输入，直到下一拍快照含本条 `message_id`（防重发）。
- **前端绝不内嵌任何 NPC AI/对话逻辑**：NPC 元信息从 hello+快照取，对话只读快照（违反「对话纯走世界拍」即红线）。

### 7.6 日夜与音效

- **日夜**：`DayNight(CanvasModulate)` 按快照 `world_time` 所属时段（5:00 清晨 / 8:00 白天 / 17:30 黄昏 / 20:00 夜）在关键帧颜色间插值；纯前端表现。

## 9. 好感度薄层设计

**全部落 `cyber_town/backend/affinity/`，不改引擎。**

**持久化**：独立 SQLite `cyber_town/backend/data/affinity.db`（自持 `sqlite3` 连接；**每次 apply 成功后立即 commit**）。**不写进** `agent_world/persistence/schema/world/`（引擎 `WorldDB.init_schema()` 会 `executescript` 该目录所有 `.sql`，`world_db.py:95-100`——往那放表=改底座触红线）。与 world.db 非原子是**预期行为**（好感度软状态可重算），tick_loop 处加注释说明。

```sql
CREATE TABLE IF NOT EXISTS affinity (
  npc_id      INTEGER NOT NULL,    -- 持有态度方（必须是 NPC；写入前校验 npc_id != PLAYER_ID）
  other_id    INTEGER NOT NULL,    -- 指向对象（其他 NPC 或玩家）
  score       INTEGER NOT NULL DEFAULT 10,   -- 0-100，clamp
  level       TEXT    NOT NULL DEFAULT 'stranger',
  updated_at  INTEGER NOT NULL DEFAULT 0,
  last_reason TEXT,
  PRIMARY KEY (npc_id, other_id)
);
```

**5 档（阈值集中 `AffinityManager.level_of`，可调）**：`<20 陌生 / 20-39 熟悉 / 40-59 友好 / 60-79 亲密 / >=80 挚友`。

**更新策略 = 主路 piggyback + 兜底规则法（零额外 LLM 调用）**：

- **主路**：给 NPC 的 TOOLS 增 cyber_town 私有工具 `adjust_affinity(target, delta, reason)`。引擎对一拍多 tool_calls **全量 dispatch**（审计已核实），故 NPC 可同拍产出 `adjust_affinity`+`speak_to_local`。**关键正确性点**：dispatcher 不认识它 → coerce 失败 → `unknown_action` **静默丢弃**（`dispatcher.py:180-194`）——`CyberTownNPC` 必须在把 tool_calls 返回给 `_run_place` **之前遍历抽走全部** `adjust_affinity` 交 `AffinityManager.apply_llm_delta`，其余标准动作再返回。漏做则好感度整体失效且无报错。delta clamp `[-3,+5]`。
- **兜底（规则法，tick_loop 末跑）**：**直接查 `world_db`**（`fetch_arrived_for` / `fetch_overhear_for`，与 `perception.py:202-207` 同款查询）——不依赖 obs（obs 是 NPC `perform_action_by_llm` 内的局部变量，tick_loop 拿不到；`run_one_tick` 的 report 也只有 `{t,next_t,active,places,failures}` 五个键）。按 `DirectMessageRow.sender_id == PLAYER_ID` 识别玩家消息：`speak_to_local`+2 / `send_message`+1 / 同地点共处 +0.5/拍 / 连续≥10 拍无互动 -1 衰减。每对单拍累计 clamp `[-2,+5]`，最终 score clamp `[0,100]`。
- **两路叠加**：主路防滥调（clamp 收紧），规则法做底噪。

**注入**（第 6 段，NPC 自己拼，不动前 5 段）：`render_affinity_block(npc_id, present_ids, name_directory)` → 只渲染**在场者**控 token：

```
# 我对在场各人的态度
- 老钱(杂货铺老板): 友好 52/100（他常照顾生意）——可热络、愿攀谈
- 农场主(玩家): 陌生 12/100——还不熟，保持客气距离
```

每档附行为指引（陌生→客气有距离 / 友好→主动攀谈 / 亲密→交心可托付 / 挚友→无话不谈）。perception.build 或 LLM 异常时整体降级为空 tool_calls、好感度段跳过拼接（与 DemoAgent 同款 fail-soft）。

**种子**：启动期灌入初始底色（老钱↔阿香=友好45、大山↔玩家=熟悉30、其余=陌生10），`AffinityStore.seed()` 幂等。`snapshot` 给 WS：`{"affinity":{npc_id:{other_id:{score,level}}}}`。

- **改动点**：新建 affinity 模块 + NPC 宿主接线，零引擎改动。

**贯穿全程不变量**：F2F `arrive_at=t` 同拍同地点可见；RDC/GRP/MOVE 锁步下拍；`world.t` 每拍必进；玩家 `request_move` 当拍仍在旧地点；`UPDATE_STATE` 下拍 perception 才读到；玩家动作经同一 `ActionDispatcher.dispatch` 与 NPC 等权。
