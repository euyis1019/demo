# 调研：Godot 4.6 Web 端 3D 可行性 + 现有 2D 农场小镇能否转 3D（W10）

> 结论先行：**引擎能做**低多边形 Web 3D；但对这个已有成熟 2D 系统的单人 demo，
> **满 3D 不划算**；唯一值得做的是「3D 地面 + 2D 立绘 billboard」的**伪 3D**，
> 且应先做一个独立 spike 验证体积/帧率再决定。

## 1. Godot 4.x 的 3D 能否稳定导出 Web 跑？——能，但有天花板

- **唯一渲染路径**：Web 导出只能用 **Compatibility 渲染器（WebGL2）**；Forward+/Mobile
  需 Vulkan/现代 API，Web 不可用，WebGPU 尚未落地。
- **3D 阴影**：4.2 起 Compatibility（含 Web）已支持（PR #77496）。我们用 4.6，可用。
- **3D MSAA**：4.3 起 Compatibility 可用（2D MSAA 仍未实现）。
- **被禁用**：`VisibleOnScreenNotifier3D`（剔除优化）在 Compatibility 下不可用；
  SDFGI/SSAO/SSR/体积雾等高级光照 Web 上没有 → 画质上限明显低于桌面 Forward+。
- **单线程 WASM**：是 4.3+ 默认且推荐（避开 SharedArrayBuffer，对 itch.io 等最友好，
  我们的 `thread_support=false` 正是此档）；复杂 3D 场景主线程压力更大。
- **真实性能数据**：一个 3D 平台跳跃原型经优化（Compatibility + Basis Universal）
  达成「体积 120MB→35MB、MacBook Air 20→58 FPS、iPhone 15 60 FPS」。即
  **低多边形 3D Web 可达 60FPS，但不优化默认就是 100MB+ / 20FPS 卡顿**。

## 2. 三渲染器 × Web

| 渲染器 | Web | 3D 影响 |
|---|---|---|
| Forward+ | ❌ | 桌面专用 |
| Mobile | ❌ | 需现代 API |
| **Compatibility (WebGL2)** | ✅ 唯一 | 阴影(4.2+)/MSAA(4.3+)可用；无高级光照 |

## 3. 公开成品/案例（证明可行）

- **官方 demo（浏览器直接玩）**：<https://godotengine.github.io/godot-demo-projects/>
  含 Truck Town、Platformer 3D、Character 3D、3D Lights and Shadows、3D Navigation 等
  ~20 个 3D demo → 3D 角色移动+光影+导航在 Web 稳定可跑。
- **3D Truck Town**（社区导出 4.4）：<https://digitalstudios10.itch.io/3d-truck-town-demo>
- **itch.io 3D+Godot HTML5 合集**：<https://itch.io/games/html5/tag-3d/tag-godot>
- 共性：成功案例**清一色低多边形 / 卡通 / 小场景**，规模与「3 地点小镇」匹配；
  没有大世界写实 3D。

## 4. 2D→3D 的现实路径与代价

**最大利好——后端/协议零冲击**：WebSocket 传的是逻辑坐标 + place_id + 状态，
与 2D/3D 无关。转 3D 前端只需把坐标从 `Vector2(x,y)` 映射成 `Vector3(x,0,y)`；
后端、好感度、对话总线、`request_move`、快照分发**全不用动**。受冲击的只有
「前端怎么画」那一层（`main/player/npc/sprite_lib/day_night` ≈ 1400 行需改），
`phone_menu`/`world_net`/`config` 基本可留。

- **方案 A（满 3D）**：节点全换（Node3D/CharacterBody3D/Camera3D/GridMap/
  DirectionalLight3D…）、2D shader 全部重写为 spatial、2D 像素素材全废、需全新
  网格+骨骼动画模型 → 前端 ~1400 行基本重写 + 新资产 + Web 调优。**对单人 demo 是重活，不建议。**
- **方案 B（伪 3D，推荐切入）**：
  - **B1（Don't Starve 式）**：3D 地面/建筑（低多边形）+ 角色用 `Sprite3D`(billboard)
    **复用现有 2D 立绘**。性价比最高：只换地面与建筑，拿到立体感 + 熟悉角色，
    无骨骼动画开销，体积/性能友好。
  - **B2（Stardew 式）**：正交相机 + 几乎全 2D 的「带角度俯视」——**我们现在的 2D 已在此谱系**。
- **CC0 资产来源**（满 3D / 伪 3D 地面需要）：
  - Kenney [Nature Kit](https://kenney.nl/assets/nature-kit) / [City Kit] / [Food Kit]（CC0，glTF）
  - KayKit [Adventurers 角色包](https://kaylousberg.com/game-assets/characters-adventurers)（CC0，含骨骼+动画）
  - 现用 Ninja Adventure 是 2D 像素，转真 3D 需全新模型。

## 5. 推荐与最小验证实验

**评级**：引擎「能做 Web 低多边形 3D」=**能**；方案 A 满 3D 用于本 demo=**不建议**；
方案 B1 伪 3D=**勉强可行、唯一值得的切入**。

**推荐**：现阶段**不转满 3D**——已有 ~2300 行打磨过的 2D 表现层，星露谷本就是
俯视 2.5D，美术目标用现路线已能达成；满 3D 要废弃全部 2D 资产/系统并背上 Web
单线程/体积/无剔除包袱，产出有限。要走 3D 就只走 B1，且**先 spike 后投入**。

**最小验证实验（独立小工程，不碰主分支、不动后端）**：
1. `Node3D` 根 + 正交 `Camera3D` 俯视 + `PlaneMesh`/Kenney Nature glTF 摆件做地面；
2. 1~3 个 `Sprite3D`(billboard) 贴**现有 Ninja Adventure 角色帧**，键盘 `Vector3` 移动，
   验证「2D 立绘站 3D 地面、随相机朝向、深度遮挡正确」；
3. 加 `DirectionalLight3D`(shadow) + `WorldEnvironment`，导出 Web（Compatibility +
   `thread_support=false` + VRAM/Basis Universal 压缩），Chrome/Firefox 实测
   **FPS / 首包体积 / 加载时间 / 阴影**。基线目标：体积 <40MB、桌面 ≥50FPS。
4. 用 spike 的观感与数据对照现 2D 版做「值不值」决策。
